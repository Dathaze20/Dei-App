# v0.1.4 notes: one combined update (v0.1.3 + v0.1.4), approved releases publish themselves

## 1. Release plan

- **v0.1.3 was never published.** Its draft (id 419542004) is left as it is: it was not published or deleted.
- **v0.1.4 (versionCode 1004) contains all of v0.1.3** and installs directly over v0.1.2 (1002). Android only needs a higher versionCode, and the updater only offers published releases, so the v0.1.3 draft is never offered (`utils/appUpdate.test.ts`).
- **Upgrading from v0.1.2.** All v0.1.3/v0.1.4 data starts empty and is created only when first used. Nothing existing is changed:
  - order history: `inventory_orderHistory`;
  - backup log: `deliordernyc_sys_backupLog`;
  - working place: `deliordernyc_sys_place`;
  - photos: the IndexedDB database `deliordernyc-photos`.

  `e2e/v013.spec.ts` › "migration from v0.1.2" loads v0.1.2 storage and checks every key is unchanged.
- **Approved releases publish themselves:** docs/ANDROID.md › "Making a release".

## 2. What v0.1.4 adds on top of v0.1.3

- **Add photos (one-handed).**
  - Opened from Catalog › Add photos, or from a product's details › Add photo.
  - It shows one product at a time, in Counter order, with Take photo, Choose photo and Skip.
  - Saving a photo moves straight to the next product that still has none.
- **Needs attention › Add to order.** Products at or below their reorder point get a "+" that adds one case to the order. You change the quantity in the tray; there is no suggested amount.
- **Order history.**
  - Each supplier's order shows "Last saved order: date · Prepared/Sent". Tapping it opens history filtered to that supplier.
  - "Use as current order" lets you untick lines. It still asks first, and replaces only that supplier's lines.
- **Your place is kept even if Android closes the app.** Each supplier's scroll position and the open or closed sections are saved on the phone. The key is device-only and never backed up.
- **Backup reminder.**
  - It is now one short line: "No backup saved from this phone yet" / "Last backup N days ago", with Back up and ×.
  - The honest status in Settings is unchanged.
- **Camera help.** Where photos are taken, a line explains what to do if the camera does not open: allow Camera for DeliOrderNYC in Android Settings.
- **Faster photo lists.** One IndexedDB connection is shared instead of one per photo.

## 3. Evaluated, not built (and why)

- **One combined backup file (data + photos).** Not built.
  - The main backup is verified by a checksum over its data. A file with photos inside would have to be a new format.
  - v0.1.2 could not restore that format, and a phone that lost the app would need the newest version to read it.
  - Two files keep the main backup readable by every version. Export My Data already says how many photos are not in it.
  - A combined format can be added later as an *extra* option with its own version number and validator. It would never replace the existing file.
- **Barcode scanning.** Not built yet.
  - Search already matches UPCs, and CSV import accepts them.
  - A scanner needs live camera access (`getUserMedia`) inside the Android WebView, plus a decoder. `html5-qrcode` is already a dependency; Chrome's `BarcodeDetector` is not available everywhere.
  - Neither can be checked without the real phone. A button that might not work would break the "no fake camera buttons" rule.
  - **Next step:** a Scan button in Counter search that fills the search box with the decoded UPC (local products only), tested on the Galaxy A17 first.
  - Any online product lookup must be optional, name its provider and cost, and keep no key in the APK.

## 4. Camera-assisted counting: the remaining steps

1. **Barcode first** (above). It has no AI, gives certain identification, and is useful for adding products.
2. **Shelf photo capture.** Photos go into the existing photo store with `kind: 'shelf'`, never attached to a product automatically.
3. **Recognition** returns *proposals* (`{ productId, units, confidence }`): pure code, never writing storage. On-device or opt-in online; nothing is sent without asking.
4. **Review sheet.** Each proposal sits next to the verified count; the person edits or ticks it.
5. **Saving.** Only ticked proposals go through `saveStockCount(id, units, 'camera-confirmed')`. An estimate is never shown as verified.

## 5. AI assistant: ready, not built

- **Data it will use (all exist):**
  - `getStock` (verified / unverified / unavailable / not tracked);
  - `attentionList`;
  - `orderHistory` (what was ordered and when);
  - `supplierDraftSummary` (the current order).
- **What it may say:** verified counts with their date; unknown stock as unknown. Reorder ideas are labelled suggestions with their reason.
- **Placement:** unchanged (docs/V0.1.3_NOTES.md §10). The bottom bar and tray already leave the space, and nothing placeholder was added.
- **Keys and data:** no key in the APK. Nothing is sent anywhere without explicit permission naming the provider.
